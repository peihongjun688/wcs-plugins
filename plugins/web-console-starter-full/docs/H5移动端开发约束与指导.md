# H5 移动端开发约束与指导（Mobile H5 Spec）

> web-console-starter · 手机浏览器 H5 的**适配层**规格。**v1.2.0 起视觉层已升级**：H5 页面不再只是"桌面 CSS 单列降级"，而是由 `docs/H5视觉规范v2.0.md` 定义的**独立玻璃视觉**（底部 TabBar / 彩色 SVG 图标 / 6 套独立皮肤 / 玻璃卡片），5 类业务模板页均为桌面/H5 **双形态分支**（`useH5()` + `v-if`，见 AI-GUIDE §5）。本文件只管"在哪些尺寸下怎么布局与适配"（断点/触控/字号/全局兜底），视觉规格一律以 H5视觉规范v2.0.md 为准。
> 配套阅读：`docs/H5视觉规范v2.0.md`（★H5 视觉契约）、`docs/设计规范.md`（桌面 token 契约）、`frontend/src/style.base.css`（移动端全局适配段）、`frontend/src/layout/Layout.vue`（TabBar + 抽屉 + /dashboard↔/h5 切换）。

---

## 1. 断点体系（唯一真源）

模板只认两个断点，**新增页面一律沿用，禁止另造断点值**：

| 断点 | 形态 | 布局 |
|---|---|---|
| `> 1100px` | 桌面宽屏 | 侧栏 220px + 内容多列 |
| `769px ~ 1100px` | 桌面窄窗 / 平板横屏 | 侧栏保留，内容区 1~2 列降级（沿用各页 1100 断点） |
| `≤ 768px` | **手机 H5 / 平板竖屏** | 见下方"v2.0 移动端形态" |

实现位置：
- `Layout.vue` 用 `window.matchMedia('(max-width: 768px)')` 驱动 `isMobile`：渲染底部 `MobileTabBar`、把 `/dashboard` 自动切到 `/h5`（总览的 H5 形态）。
- 业务页模板用 `@/useH5` 的 `useH5()` 拿响应式 `isH5`，写 `<div v-if="isH5">…H5 布局…</div><div v-else>…桌面…</div>` **双形态分支**（数据逻辑共用一份），不要再写 `@media (max-width:768px)` 去压桌面组件。
- 旧页面若仍是"纯 CSS 降级"写法（v1.1.0 遗产），新开发一律按双形态分支迁移；全局兜底（弹窗防溢出/输入字号/触控）仍在 `style.base.css` 的 H5 段。

**v2.0 移动端形态总览**：顶栏汉堡 + 抽屉（"全部模块"入口）仍在；底部新增固定 TabBar（总览/告警/中间凸起"全部"/趋势/我的）；总览 `/dashboard` → 自动跳 `/h5`；业务页各自 H5 形态；H5 皮肤 6 套独立于桌面（设置页可切、即时生效记忆）。

**规则**：页面想表达"窄了就单列"，直接写 1100px 断点即可（移动端自然继承）；H5 专属布局不写媒体查询，直接用 `isH5` 分支。

## 2. 移动端布局契约（Layout.vue 已内置，业务页无需重复）

| 元素 | ≤768px 行为 | 说明 |
|---|---|---|
| 侧栏 el-aside | 不渲染 | 菜单改由抽屉承载，同一份 menus 数据 |
| 顶栏 | 高 52px、内边距收窄 | 汉堡按钮出现在最左（`Expand` 图标，circle text） |
| 导航 | 汉堡 → 左滑抽屉（240px，ltr） | 点菜单项自动跳转并收起；拉宽回桌面自动收起 |
| 皮肤预览下拉 | 隐藏 | 桌面才显示；移动端换肤走「系统设置」页 |
| 刷新 / 用户菜单 | 保留 | 用户名在窄屏截断为 72px 内 |
| 内容区 .main | 内边距 12px | 桌面 18px |

**抽屉导航样式**：`.nav-drawer` 由 `Layout.vue` scoped 段控制，配色仍走 `--panel-solid/--panel-bd/--menu-active-*`，**不引入移动专属颜色**。

## 3. 触控与阅读规格（H5 硬性约束）

| 项 | 规格 | 说明 |
|---|---|---|
| 主要触控目标 | 高度 ≥ 36px，推荐 44px | 侧栏菜单 44px、按钮 `size="default"`；`size="small"` 仅限次要行内操作 |
| 正文最小字号 | 13px | 移动端 `body` 已设 13px（桌面 13px 不变） |
| 输入框字号 | ≥ 16px | 防 iOS 聚焦自动放大：全局已把 `.el-input__inner/.el-textarea__inner` 在 ≤768px 设为 16px，**新增自定义输入框同样遵守** |
| 点击热区 | 不相邻目标间距 ≥ 8px | 行内 `el-button link` 若连续排列，窄屏保留可点高度 |
| 横向滚动 | 只允许表格容器内 | 页面 body 禁止横向溢出；`overflow-x` 只出现在 `.el-table__body-wrapper` |

**禁止事项**：
- 不写 `min-width` 大于视口的容器；不用固定 px 宽把内容撑出屏幕（工具条控件在 ≤768px 会被强制 `width:100%`）。
- 不给 `.panel` / 页面根 div 加 `overflow:hidden` 横向截断（会吃掉表格滚动与抽屉）。
- 不在移动端隐藏"操作列"或把删除等行为塞进层级过深（≥3 次点击）。

## 4. 页面模板在 H5 的形态（5 类 + 设置）

| 模板 | 桌面 | ≤768px 形态 | 已在模板中实现 |
|---|---|---|---|
| 登录 Login | 居中 380px 玻璃卡 | 卡片 `max-width: calc(100vw - 32px)` 自动收缩，贴顶留 6vh 呼吸 | ✓（Login.vue） |
| 总览 Dashboard | KPI 4 列 + 双图表行 | KPI 单列大卡、状态横幅换行、图表与列表单列 | ✓（Dashboard.vue 768 段） |
| 列表 CRUD | 工具条 + 表格 + 分页 | 搜索/筛选控件全宽单列；表格保持原生横向滚动（列多时左右滑）；分页居中 | ✓（CrudPage.vue 768 段） |
| 趋势 Trend | 顶栏时间范围 + 全宽图 + 双栏 | 时间范围按钮随面板头换行（全局 `.panel-hd` wrap）；图表单列 | ✓（全局适配） |
| 明细 Detail | 指标网格 8 + 大图 + 明细表 | 指标网格 2 列（复用 1100 断点）；明细表横向滚动 | ✓ |
| 设置 Settings | 皮肤网格 2 列 + 双栏 | 皮肤卡 1 列、信息单列 | ✓（1100 断点已覆盖） |

> **新增业务页清单**（任何新页面过这些才算移动可用）：
> 1. 布局用 `PanelCard` 堆叠或行内 `grid`，且所有栅格列都有 ≤1100 的单列降级；
> 2. 工具条表单控件不写死宽度（或允许窄屏 100%）；
> 3. 表格不做移动端特判——用 el-table 原生横向滚动 + `fixed="right"` 操作列；
> 4. 弹窗/消息框宽度 ≤ `calc(100vw - 24px)`（全局已兜底，业务自定义浮层同样遵守）；
> 5. 图表统一 `<BaseChart>`（自带 ResizeObserver 与皮肤主题，移动旋转/切换标签后仍正确）。

## 5. 图表在 H5 的约束

- **高度**：移动端建议图表高度 **220~280px**（桌面 260~320px）。若业务图想随屏变高，可在 768 断点改传给 BaseChart 的 `height` prop（或计算属性）。
- **tooltip**：默认 `trigger:'axis'|'item'` 在触摸屏上以点按触发，无需特判。
- **图例**：多系列图在窄屏若图例挤占，允许 `legend: { top: 0 }` + 图表 `grid.top` 相应下调（参考 Dashboard 双线图的 grid 值）。
- 不因移动端改变数据聚合逻辑；报表仍须真实数据聚合（见设计规范/软著红线）。

## 6. 与皮肤 token 的关系（零新增）

H5 **不新增任何 token**：移动布局全部复用桌面 token（`--bg-*/--panel*/--txt*/--accent*/--menu-active-*` 等）。移动端验收同样按 4 套皮肤逐套截图，颜色破版即视为失败。
深色玻璃皮肤的 `backdrop-filter` 在移动端保留（现代 iOS/Android 均支持）；如遇低端机性能问题，可在皮肤文件按需弱化，但**不得**为移动端另做一套颜色。

## 7. H5 验收清单（收工前逐项过）

- [ ] 汉堡按钮出现，抽屉左滑正常，菜单跳转后自动收起，拉宽回桌面侧栏恢复
- [ ] 工具条控件在窄屏单列/不挤压；表格可左右滑动且操作列可达
- [ ] 弹窗/消息框/下拉在窄屏不超出屏幕
- [ ] 图表随容器自适应，无 0 尺寸白块；旋转屏幕/切换路由回来仍正常
- [ ] 触控目标抽查：主要操作（登录、新建、保存、删除确认）单手可点且不易误触

- [ ] 真实手机（或用 DevTools 移动模拟）登录 → 增删改 → 出图全流程走通，如实汇报失败项

## 8. 高频移动踩坑（模板已解决 / 新增业务要注意）

| 症状 | 根因 | 处理 |
|---|---|---|
| iOS 点输入框页面放大 | input font-size <16px | 输入类字号 ≥16px（全局已做，新控件同样） |
| 抽屉/弹窗在窄屏溢出 | 固定宽度未收缩 | 弹层 `max-width: calc(100vw - 24px)`（全局已兜底）；自定义浮层自查 |
| 表格操作列在手机看不到 | 外层 overflow 截断 | el-table 原生滚动 + `fixed="right"`；禁止外层横向截断 |
| 旋转/切页后图表白块 | 容器尺寸变化未通知 | 只用 `<BaseChart>`（内置 ResizeObserver） |
| 面板头控件挤压换行 | 标题与 extra 同行 | 全局 ≤768px `.panel-hd` wrap 已处理；自定义头部自行 wrap |
| 双击缩放/双击误触 | 无 `touch-action` 约束 | 仅表格滚动区保留触摸滚动，正文区正常（默认即可，勿全局禁用手势） |
