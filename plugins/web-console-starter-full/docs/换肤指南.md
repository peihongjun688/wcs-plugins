# 换肤指南（Skin Guide）

> web-console-starter 的换肤 = **只换 `themes/<皮肤>.css` 里的 CSS 变量**，组件/布局零改动。
> 预置：`deep-blue`（默认）/ `light-pro` / `emerald-dark` / `royal-purple`。新增皮肤只需一个主色。

---

## 1. 换肤的三种入口（优先级从高到低）

| 入口 | 用法 | 场景 |
|---|---|---|
| 运行时预览 | 登录页/顶栏/设置页的皮肤下拉 → 写入 `localStorage` 后整页重载 | 定稿前肉眼挑皮肤 |
| 单点配置 | `app.config.js` → `skin: 'light-pro'` | 产品定稿，随包生效 |
| 直改 html | `<html data-skin="xxx">`（由 main.js 设置） | 高级/调试 |

生效顺序：`localStorage（预览） > app.config.skin > deep-blue 兜底`。
预览 key：`${cfg.localKey || cfg.name}_skin`（如 `MyConsole_skin`），清除该 key 即回到配置皮肤。

## 2. 机制（怎么生效的）

```
main.js boot():
  1. resolveSkin() 取皮肤名
  2. <html data-skin="name">          ← 主题 css 顶层选择器
  3. import.meta.glob 动态 import themes/<name>.css   ← 懒加载，不进主包
  4. 读 --app-mode → <html> 挂/卸 dark class          ← Element Plus 明暗联动
  5. 挂载 App → 构建守卫（buildinfo 时间戳）
```

- 皮肤 CSS 只允许出现在 `<html data-skin="xxx">` 作用域内（或直接全局变量覆盖），互不污染。
- ECharts 不需要单独换肤：`app.theme.js` 每次从 CSS 变量实时读取色盘注册 `'app'` 主题，图表跟随。
- 构建产物里 4 套皮肤是**独立 CSS chunk**（见 vite 输出），未选中的皮肤不加载、不影响首屏。

## 3. token 契约速查（每套皮肤必须齐全）

背景/面板：`--bg-0 --bg-1 --panel --panel-bd --panel-solid --side-bg --top-bg`
文字：`--txt --txt-dim --txt-strong`
强调/按钮：`--accent --accent2 --logo-fg --btn-fg`
组件态：`--menu-active-bg --menu-active-txt --hover-bg --input-bg --input-bd --line --track`
图表：`--chart-1 … --chart-10`
模式：`--app-mode: dark|light`

新增变量 → **4 套皮肤全部补齐** → 组件才引用，保持"组件零硬编码"纪律。

## 4. 新增皮肤（推荐用脚本）

```powershell
# 生成一套与主色协调的完整皮肤（自动推导同色系变量 + 10 色图表盘）
powershell -ExecutionPolicy Bypass -File scripts/new-skin.ps1 -Accent #34d399 -Name emerald-dark -Mode dark
```

生成后需要两步登记：
1. 确认 `frontend/src/themes/<Name>.css` 内容合格（对比现有皮肤）；
2. 在 `frontend/src/app.skin.js` 的 `SKINS` 里登记显示名（否则设置页下拉不出现）。

> 脚本为纯 ASCII（PS5.1 GBK 控制台安全）。混色依赖 `color-mix`，浏览器需较新版本；构建侧无影响。

## 5. 深浅色与 Element Plus 覆盖清单

暗色由 `<html class="dark">` 驱动 EP 组件自动翻转，以下仍须在 `style.base.css` 显式覆盖（防破版）：

| 组件 | 覆盖项 |
|---|---|
| 主按钮 | 渐变背景 + `--btn-fg` 文字 |
| 菜单激活 | `--menu-active-bg/--menu-active-txt` |
| 输入框 | `--input-bg/--input-bd`（focus 用 accent） |
| 表格 hover/边框 | `--hover-bg` / `--line` |
| 弹窗/下拉/日历 | 不透明底 `--panel-solid`（半透明会叠穿） |
| 滚动条 | accent 淡色 + 透明轨道 |

## 6. 验收标准（换肤是否"破版"）

1. `npm run build` 通过，产物含 `<皮肤名>-*.css` 独立 chunk；
2. 4 套皮肤各打开：登录/总览/列表/趋势/详情/设置 六页，**文字可读、按钮可见、图表配色协调**；
3. 浅色皮肤（light-pro）重点查：白字贴白底、暗色残留块、玻璃叠加失效；
4. 运行时下拉切换皮肤，刷新后仍保持（localStorage）。

破版 90% 的根因只有一个：**组件或页面里写死了颜色**（尤其 `rgba(255,255,255,x)`）。遇到破版先 grep 硬编码颜色，不要改皮肤。

## 7. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| 换肤后颜色没变 | 只改了配置没重载 / 皮肤名拼错 | localStorage 清了刷新；核对 SKINS 键名 |
| EP 弹层一片黑/叠穿 | 用半透明底弹窗 | 改用 `--panel-solid` |
| 图表色不变 | 主题注册在皮肤加载前执行 | 确认走 BaseChart 统一入口（注册时序内置） |
| light-pro 下白底白字 | 组件硬编码白色 | 删硬编码，改变量 |
